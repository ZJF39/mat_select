# 05 · 交互与状态清单

> 这份文档回答三个问题：**主流程怎么走**、**每个数据面有哪几种状态**、**键盘和动效要注意什么**。
> 原型是静态图，所有「四态」都需要实现层补齐——这是本包最容易漏项的部分。

---

## 1. 三条主流程

### 1.1 选材主流程（最高频，验收重点）

```
① 进入「智能推荐」→ 自动落在最近一条任务，或点「新建选型任务」
② 输入自然语言需求（占位符给真实示例）
③ 系统回显【可编辑的约束标签】+ 置信度 + 未识别内容说明
④ 用户修正约束 → 点【确认约束并生成推荐】        ← 硬约束必须由人确认
⑤ 推荐结果以卡片进入会话流，首位全展开（理由/关键参数/注意/替代/分数拆解）
⑥ 逐条【加入待选】→ 右侧面板实时新增并高亮
⑦ 追问（如「再便宜点」）→ 系统回复「已按成本敏感重新加权」+ 刷新后的列表
⑧ 底部回评条 → ✅成功 / ❌失败（弹窗必填理由） / ⏭暂不评价
⑨ 任务可导出 Markdown / 归档
```

**关键交互约束**
- ③→④ 之间**不允许出结果**。这是「把模型理解变成用户确认过的硬约束」的硬性要求（PRD B1）。
- ④ 结果为空时**不放宽就不返回**（后端返回 `degraded` 时，UI 显示放宽了什么，并给「恢复原约束」入口）。
- ⑥ 同一任务内同一材料不重复入待选（后端 `UNIQUE(task_id, material_id)`），前端按钮要能识别并显示「已在待选」。
- ⑧ 不做回评直接关闭界面 = `skipped`，**不得**计为失败。

### 1.2 回评闭环（数据质量的生命线）

```
回评条 → 选「失败」→ 弹窗（理由必填 / 问题类型多选 / 指向材料可选）
     → 提交 → 后端语义拆解 → 命中材料写 negative_feedback；未命中写 requirement_gap
     → 关闭弹窗 + 轻提示「已记录，下次推荐会参考这条反馈」
     → 回评条变为「已回评：失败 · 时间」并提供「修改回评」
```
- 弹窗内的**拆解预览**必须与后端实际拆解一致（预览可以前端按同一套规则做，或提交前调一次 dry-run）。
- 「清空我的反馈」在设置页，危险样式 + 二次确认。

### 1.3 分享闭环（导出 → 导入）

```
导出：选范围 → 选格式 → （可选）包含个人数据 → 预览文件名与体积 → 导出
导入：拖入 JSON → 本地校验（版本/校验和/必填）→ 预览统计（新增/更新/冲突/失败）
     → 选冲突策略 → 确认导入 → 重建检索与向量 → 刷新材料计数
```
- 校验失败**必须拒绝写库**（不产生半截数据），错误信息要说清是哪一类问题。

## 2. 每个数据面的「四态」清单

> 实现时逐个打勾，缺一不可。原型只画了默认态与部分空态。

| 数据面 | 加载态 | 空态 | 错误态 | 成功反馈 |
| --- | --- | --- | --- | --- |
| 材料卡片网格（01） | 6 张卡片骨架屏（保留外框，内部灰条，禁用筛选） | 「未找到匹配材料 / 试试减少筛选条件」+ `清除全部筛选` | 区块内联危险提示条 + `重试`（不清筛选） | 进入详情 |
| 材料表格（02） | 12 行骨架行 | 同 01 | 表体中部提示条 + `重试` | 导出成功轻提示 |
| 分类树（01/02/03/07/08） | 树行骨架（3 行） | 「暂无分类，点击『管理分类体系』创建」 | 树区域重试按钮 | 增删改后轻提示 |
| 材料详情（03） | 卡片骨架 ×4 | 字段级 `—`（不隐藏行）；整体为空态表示 uid 不存在 | 404 → 全页空态 + `返回材料库` | 保存/加入待选轻提示 |
| 会话流（04） | 「正在解析约束…」占位消息 + 禁用发送 | 新任务空态：一句引导 + 3 个示例需求可点（`换个说法` 也在此） | 解析失败 → 警示条 + 就地提供工艺/温度下拉 | 推荐结果插入动画 |
| 推荐结果 | 卡片骨架 ×2 | **不用空列表**：优化提示条 + `放宽条件再试` / `修改约束` | 同上 | 分数拆解 hover 有 Tooltip |
| 任务列表（04/05） | 4 项骨架 | 「还没有任务，输入一句话开始选材」+ `新建选型任务` | 面板内重试 | 归档后轻提示 + 列表移除 |
| 待选面板（04） | 2 项骨架 | 「从上方推荐结果点击『+ 加入待选』，把感兴趣的材料收进来」 | 面板内重试 | 新增高亮 600ms；备注「已保存」 |
| 对比表（05） | 4 行骨架 | 「待选还是空的，回到任务会话收集候选材料」 | 重试 | 备注保存轻提示 |
| 编辑表单（07） | 表单骨架（保留 label 占位） | 不适用 | 字段级错误 + 顶部汇总条（「有 2 处需要修正」） | 「保存成功 · 已生成 v3 快照」 |
| diff（08） | diff 行骨架 | 「该材料还没有变更记录」 | 重试 | 恢复成功 → 跳详情 |
| 导出/导入（09） | 导出按钮 loading；导入解析中落区进度 | 「还没有导出过」记录空态 | 校验失败提示条（明确原因）+ `重新选择文件` | 导出：文件下载 + 记录；导入：`已导入 14 条` |
| 设置（10） | 滑杆区骨架 | 盲区报告无数据：「本周没有失败回评」 | 重试 | 「配置已保存」 |

**通用规则**
- 加载态用**骨架屏**（形状与实际内容一致），不用居中转圈。
- 错误态**内联在出错的区块**，不用全局弹窗（除非是致命错误）。
- 任何写操作都要有**成功反馈**（轻提示或状态变化），静默是缺陷。
- 可逆操作（归档、移出待选、恢复版本）优先提供「撤销」。

## 3. 键盘与可达性

| 场景 | 按键 |
| --- | --- |
| 全局搜索 | `Ctrl/Cmd + K` 聚焦；`Esc` 清空并失焦；`Enter` 跳 01 屏 |
| 会话发送 | `Enter` 发送，`Shift + Enter` 换行（占位区已写明） |
| 分类树 | `↑/↓` 移动、`→` 展开、`←` 收起、`Enter` 选中 |
| 筛选项 Popover | `Esc` 关闭；`Tab` 在选项间移动；多选用 `Space` 切换 |
| 待选排序 | 手柄聚焦后 `Space` 提起 → `↑/↓` 移动 → `Space` 放下；`aria-live="polite"` 播报「已移动到第 2 位」 |
| 滑杆 | `←/→` 步进 1，`Shift + ←/→` 步进 5，`Home/End` 到边界 |
| Modal | 打开后焦点移入弹窗并锁定；`Esc` 关闭（有未保存内容时先确认）；关闭后焦点回到触发按钮 |

**语义与标签**
- 图标按钮必须有 `aria-label`（如 `编辑材料`、`查看变更历史`）。
- 材料卡片整体是可交互链接时用 `<a>`/`role="link"`，不要用 `div + onClick`。
- 匹配度、分数拆解这类数字要带可读文本（`aria-label="匹配度 95 分，由 5 个维度加权得出"`）。
- 「待验证」「重点考虑」这类标记 = 文字 + 颜色双编码，不能只有颜色。
- 焦点样式全站统一 `outline: 2px solid #1F5FD0; offset 2px`，禁止 `outline: none`。

## 4. 微交互与动效规范

| 场景 | 规格 |
| --- | --- |
| 通用过渡 | `120ms`（hover 类）/ `180ms`（展开收起）/ `220ms`（Modal） |
| 缓动 | `cubic-bezier(0.22, 0.61, 0.36, 1)` |
| 卡片 hover | 描边颜色过渡，**不上浮、不加投影、不缩放** |
| 按钮按下 | `translateY(0.5px)`，不加投影 |
| 推荐结果插入 | 淡入 + 上移 4px，`180ms`；**不要**逐条错峰超过 120ms 的延迟 |
| 待选新增 | 面板内新增项底色 `accent-soft` → 透明，`600ms` |
| 消息发送 | 用户气泡立即出现（乐观更新），失败时在气泡下方显示重发入口 |
| 骨架屏 | 静态灰块即可；如做 shimmer，仅限 1.2s 循环且尊重 `prefers-reduced-motion` |
| 禁止 | 视差、滚动劫持、粒子、外发光脉冲、超过 300ms 的过渡 |

## 5. 性能与实现注意

| 项 | 要求 |
| --- | --- |
| 首屏 | 200 条材料规模下材料库首屏渲染 < 1s（PRD 非功能要求） |
| 长列表 | 推荐结果与会话消息超过 50 条时用虚拟滚动；表格超过 200 行走分页或虚拟行 |
| 搜索 | 输入防抖 200ms；`Ctrl+K` 结果接口只取 8 条，材料/任务/场景分组展示 |
| 请求 | 材料详情、任务消息用 React Query 缓存（`staleTime` 30s），写操作后失效对应 key |
| 乐观更新 | 待选备注、标记切换、拖拽排序：先改本地再提交，失败回滚并提示 |
| 滚动 | 全站只有主内容区一个滚动容器；会话流内部独立滚动（这是唯一例外，需注意不要出现双滚动条） |
| 大文件 | 导出上限提示（如 > 2000 条建议改用 JSON）；导入解析放后端，前端只做进度展示 |
| 兜底 | 所有数值展示都要处理 `null`；所有时间展示都要处理时区（本机时区即可，单机部署无跨时区问题） |

## 6. 提测自查（与 02 章第 11 节配合使用）

1. 03 / 04 两屏用真实数据走通「选材 → 加入待选 → 回评 → 追问」全链路；
2. 07 → 08 用同一条材料走通「编辑 → 保存 → 看 diff → 恢复」，确认 diff 三色正确；
3. 09 用两台机器（或两个数据目录）走通「导出 → 导入（三种冲突策略各试一次）」；
4. 断网 / 后端停掉时，每个数据面的错误态都能出现且可重试；
5. 键盘走完 1.1 主流程，不碰鼠标；
6. 1366×768 与 1920×1080 各看一遍，确认无横向滚动、无文本截断错位。
