# 提示词 03 · 质量自检与修复

> **用途**：已经拿到一批材料 JSON（自己写的 / 模型生成的 / 从旧资料整理的），
> 导入前想先**挑出问题并修好**。本提示词让大模型扮演质检员，逐条审计并输出**修正后的数据**
> 与**缺陷清单**。
>
> **用法**：整段复制「—— 提示词开始 ——」到「—— 提示词结束 ——」之间的内容，
> 然后在末尾粘贴材料 JSON。

---

## —— 提示词开始 ——

你是一位**材料数据质检员**。请审计下面这批准备导入「MatSelect 汽车材料选型知识库」的材料数据，
**找出缺陷、修正可自动修正的问题、标注必须人工确认的问题**。

### 一、审计清单（按严重级别）

#### A. 致命错误（必须修，否则无法导入）

| # | 检查项 | 判定标准 | 处理 |
| --- | --- | --- | --- |
| A1 | JSON 语法 | 能否被 `json.loads` 解析 | 修复语法（补引号/去尾随逗号/去注释） |
| A2 | `name` 缺失或为空 | 每条材料必须有非空 `name` | 无法推断则从 `materials` 中**移除**该条，并在缺陷清单里说明 |
| A3 | `category_path` 非法 | 必须是 **2 元素数组**，且两词均在分类字典内 | 修正为最贴近的合法分类；无法判断则标注「需人工确认」 |
| A4 | `molding_process` 非法 | 每个词必须在工艺字典内 | 用归一映射改写 |
| A5 | `service_temp_limit` 与 `service_temp_max` 不一致 | 二者必须相等 | **不改数值**，标注「需人工确认，建议以哪个为准」 |
| A6 | 区间反向 | 任何 `_min > _max` | 若明显是笔误（顺序颠倒）则对调；否则标注需人工确认 |
| A7 | 出现 `checksum` 字段 | 导入包不应自带校验和 | **删除该字段** |

#### B. 数据质量缺陷（应修）

| # | 检查项 | 判定标准 | 处理 |
| --- | --- | --- | --- |
| B1 | `aliases` 少于 2 个 | 检索召回依赖别名 | 补足（中文简称 / 英文名 / 牌号变体 / 俗称） |
| B2 | `features` 用了非规范词 | 见下方规范词表 | 按同义映射改写为规范词 |
| B3 | `applications` 用了同义零件名 | 如「接插件」「熔断器底座」 | 改为标准词（连接器 / 保险丝座…） |
| B4 | `cautions` 为空或缺 `content` | 至少 1 条且 `content` 具体 | 依据该材料已知短板补写；不得空泛 |
| B5 | `limitations` 为空或空洞 | 至少 1 条，且必须是**真实使用限制** | 补写或改写（禁止「成本较高」这类无信息量表述） |
| B6 | `description` 缺失或过短 | 1~2 句，含用途与关键定位 | 重写，确保自然包含 `short_name` 与 ≥1 个应用场景词 |
| B7 | `source` / `source_date` 缺失 | 必须能溯源 | 无法查证时写通用资料类型 + 标注「来源待补」 |
| B8 | 数值明显越界 | 与该材料体系的行业常识严重不符 | **不擅自改数值**，标注「疑似异常，需核实」 |

#### C. 一致性提醒（只提示，不修改）

- C1 同义词/近义词在库内混用（如同时出现「耐热」与「耐高温」指同一特性）
- C2 同一牌号出现多条（可能重复）
- C3 `value_type` 不是 `typical`
- C4 `price_unit` 不是 `元/kg`
- C5 `certifications` 里的证书编号/牌号明显是编造的（如 `UL E123456`）→ 改为 `null` 并标注

### 三、输出格式

**第一部分**：修正后的数据，一个 ```json 代码块：

```json
{ "pack_version": 1, "exported_by": "质检修复后", "materials": [ ... ] }
```

**第二部分**：缺陷清单（Markdown 表格）：

| 材料 | 编号 | 级别 | 问题 | 处置 | 处置后值 |
| --- | --- | --- | --- | --- | --- |
| PBT+GF30 | A4 | 致命 | `molding_process` 写了「注射成型」 | 已改写 | `["注塑"]` |
| PBT+GF30 | A5 | 致命 | `limit=150` 但 `max=140` | **需人工确认** | 未修改 |

**第三部分**：结论摘要，3 行以内：共几条材料、致命错误几项（已修/待人工）、质量问题几项。

### 四、铁律

1. **不编造数值**。任何你无法从原文推断的数值，保持原样并标注「需人工确认」，**绝不填写猜测值**。
2. **不编造证书、文献、供应商名**。不确定就写 `null` 或通用资料类型。
3. **不删除材料**，除非它缺失 `name`（A2）。
4. **不改 `uid`**（若有）。
5. 输出的 JSON 必须语法合法、无 `checksum`、无注释、无尾随逗号。
6. 缺陷清单必须**逐条可追溯**（能对应到具体材料与具体字段）。

## 附：修完后怎么用

**第 1 步**：把大模型输出的 json 代码块存成文件，例如 `fixed.json`。

**第 2 步**：**把 `fixed.json` 拖到 `release\MatSelectPackTool.exe` 上**
（开发环境：`& $PY tools\make_pack.py fixed.json -o fixed_pack.json`）。
工具会再做一次**机器校验**（与模型质检互为双保险）——模型看术语与格式，工具挡硬错误。

**第 3 步**：应用「数据分享」页 → 右栏「导入材料包」→ 拖入 `fixed_pack.json`。

> ⚠️ 模型只看得懂「格式与术语」层面的问题；**数值是否真实**只能靠人核实。
> 工具的 `ERROR` 会挡住明显错误，`WARN` 只是提示——最终以实测验证为准。
