### 2.2 `.gitignore` 缺陷修复

原文件含大段重复块，且存在两处实质缺陷，本轮一并修正：

| # | 缺陷 | 影响 | 修正 |
| --- | --- | --- | --- |
| 1 | 规则 `_*.py` 同时命中 `__init__.py` | `backend/app/api/__init__.py`、`backend/app/services/__init__.py` **被静默忽略、从未入库**，远端仓库缺失包标记文件 | 以 `/_*`、`/tools/_*` 精确限定草稿范围，并追加 `!__init__.py` 例外；两个文件已恢复为待跟踪 |
| 2 | 缺少 SQLite sidecar 规则 | `data/matselect.db-wal` / `-shm` 在 `journal_mode=WAL` 下持续污染工作区状态 | 新增 `data/*.db-shm`、`data/*.db-wal` |
| 3 | 23~82 行重复块（同一批规则重复 3~4 次） | 可维护性差、易误判 | 重写为分区结构：Python / Node / 数据与运行时 / 日志 / 临时草稿 / 编辑器 / 内部数据 / 例外 |

修复验证：

```powershell

git ls-files --others --exclude-standard | Select-String __init__
# → backend/app/api/__init__.py
# → backend/app/services/__init__.py           （不再被忽略，可入库）
```

### 2.3 推荐引擎匹配能力增强（本轮一并交付）

`backend/app/services/recommend_service.py`：修复 5 类经实测暴露的匹配缺陷，**五维契约与分解恒等式未变**。

| # | 问题 | 实测现象 | 修正 |
| --- | --- | --- | --- |
| 1 | 零件类型词表覆盖不足 | 「齿轮 / 轴承 / 蜗轮 / 蜗杆」等传动承力件与「仪表板 / 格栅 / 内饰件」未归类，落入 `None` 默认力学规格 | 扩充 `PART_TYPE_DICT` |
| 2 | 维度名与数据用词不一致 | 维度「耐温」而数据写「耐热」、维度「刚性」而数据写「高刚性」，精确子串比对使整项权重被丢弃（PA66+GF30 电气件耐温权重 0.15 直接丢失） | 新增 `_FEATURE_SYNONYMS` 同义词组 |
| 3 | 增强信号未被结构化识别 | 牌号 GF30/GF40 本身即强度信号，却依赖 `features` 是否恰好写「强度」二字，致 PPS+GF40 强度项整项丢失、在结构件维度屈居末位 | 以玻纤/碳纤增强作为强度的结构化信号 |
| 4 | 力学维度重复计分 | 外观件力学规格内含「成本」，与独立成本维度（权重 20%）重复计分，使外观件力学分退化为价格排序 | 移除该重复项，改「抗冲」（内外饰件典型诉求） |
| 5 | 语义维度被长文本稀释 | 需求长文本 vs 材料长文本的 bigram 余弦绝对相似度仅 0~0.07，25% 权重维度失去区分度；且术语信号只认 36 个预设零件名，用户改用应用名词（齿轮/灯罩/密封圈）即整体失效、总分跌破 60 分门槛 → **返回空结果** | 语义维度内叠加术语命中项（`_TERM_WEIGHT=0.75` / `_COS_WEIGHT=0.25`，量纲仍 0~1），词表由**材料数据自身**派生（别名/典型应用/特性）；另以 `_DOMAIN_SYNONYM_GROUPS` 补齐领域同义表达 |

**验收证据**：`tools/verify_reco_regression.py` → **12 场景 + 权重约束全部 PASS**（默认权重 Σ=1.0000、成本优先权重 Σ=1.0000、空结果边界 `degraded=True`）；后端 62 条用例全绿。
