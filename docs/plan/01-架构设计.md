# 01 · 架构设计（MatSelect 核心底座）

> 作者：系统架构师｜状态：v1.0（框架里程碑 m1）｜依据：PRD v0.2、契约 02、原型 01–05

## 1. 分层架构

```
┌──────────────────────────────────────────────────────────────┐
│  前端 (React+TS+Vite+AntD)  http://127.0.0.1:5173            │
│   /api 代理到 127.0.0.1:8100                                  │
└───────────────────────────┬──────────────────────────────────┘
                            │ HTTP / JSON
┌───────────────────────────▼──────────────────────────────────┐
│  app/main.py  FastAPI 应用装配                                  │
│   ├─ 中间件 CORS                                                │
│   ├─ 路由自动发现：遍历 app/api/*，挂载 router 到 /api           │
│   ├─ 异常处理器：ApiError / ValidationError / 兜底 Exception     │
│   └─ lifespan：init_db() + seed_if_empty() / close_conn()       │
├──────────────────────────────────────────────────────────────┤
│  app/api/*       路由层（后端专家） —— 仅做参数与响应，不含 SQL   │
│  app/services/*  业务逻辑（后端专家） —— 推荐/解析/导出/导入     │
│  app/schemas/*   Pydantic 模型（后端专家）                      │
├──────────────────────────────────────────────────────────────┤
│  app/repository/*  数据访问层（★base.py 由架构师定稿，签名冻结）  │
│   └─ BaseRepository / query_all / query_one / scalar / execute  │
│      / execute_many / rowcount / tx()  —— SQL 集中在此层        │
├──────────────────────────────────────────────────────────────┤
│  app/db/        存储层（架构师）                               │
│   ├─ connection.py 连接池单例 + now_iso/new_uid/json 工具       │
│   ├─ schema.sql    全量 DDL（幂等 IF NOT EXISTS）              │
│   └─ init_db.py    init_db() + seed_if_empty()（容错）          │
├──────────────────────────────────────────────────────────────┤
│  app/core/      配置与横切（架构师）                           │
│   ├─ config.py  PROJECT_ROOT / DB_PATH / 权重 / 降权           │
│   ├─ errors.py  ApiError + 便捷构造（错误码与契约一致）         │
│   └─ logging.py write_log() 写 operation_log（失败吞掉）        │
└──────────────────────────────────────────────────────────────┘
         │
         ▼
   SQLite 单文件（data/matselect.db，WAL 模式，FTS5 trigram）
```

**层间依赖方向**：api → services → repository → db；core 被各层共享；禁止反向依赖（repository 不依赖 api/services，db 不依赖 repository）。

## 3. 请求生命周期与错误链路

1. 浏览器/前端 → `127.0.0.1:8100/api/...`（dev 经 Vite 代理）。
2. CORS 中间件校验来源（`127.0.0.1:5173` / `localhost:5173`）。
3. 路由命中 `app/api/*` 的 `router`；参数由 Pydantic 校验（失败 → `RequestValidationError` → 400 `VALIDATION_ERROR`）。
4. 业务经 `services` → `repository`（在此层执行 SQL，取时间统一用 `now_iso()`）。
5. 业务异常抛 `ApiError(code, message, status)` → 异常处理器 → `{"error":{"code","message"}}` + 对应 HTTP 状态。
6. 任何未捕获异常 → 兜底处理器 → 500 `INTERNAL`。
7. 成功响应**直接返回业务对象**（不包 envelope），空值一律 `null`。

**错误码表（与契约 §3.1 一致）**

| 机器码 | HTTP | 触发 |
| --- | --- | --- |
| `NOT_FOUND` | 404 | 资源不存在 |
| `VALIDATION_ERROR` | 400 | 参数校验失败 |
| `CONFLICT` | 409 | 资源冲突（如分类被引用） |
| `IMPORT_REJECTED` | 422 | 导入校验失败 |
| `INTERNAL` | 500 | 未预期异常 |

## 4. Repository 抽象与 SQLite↔PostgreSQL 可迁移口子

- **SQL 集中**：所有 `SELECT/INSERT/UPDATE/DELETE` 只在 `repository` 层出现；`services`/`api` 不直接调用 `sqlite3`。
- **统一接口**：`query_all/query_one/scalar/execute/execute_many/rowcount/tx()` 是当前所有数据访问的入口。
- **迁移路径**：二期若需多人共享（PostgreSQL），只需：
  1. 重写 `app/db/connection.py`（连接改为 psycopg，保留 `now_iso/new_uid/json_*` 语义；时间戳建议切到 DB 侧 `now()` 或 `@@timezone`）；
  2. 把 `schema.sql` 中 `INTEGER PRIMARY KEY AUTOINCREMENT→BIGSERIAL`、`JSON→JSONB`、`FTS5 trigram→tsvector+pg_trgm`、`ON DELETE CASCADE` 已原生支持；
  3. 字段结构**不变**，业务层零改动。
- **迁移风险点**：`material_fts` 触发器逻辑改为 pg 的触发器函数；`executescript` 改为分批执行。已预留 `init_db` 单点便于替换。

## 5. 实体关系（ER）说明

- `material` 1—* `material_revision`（变更快照）
- `material` 1—* `material_negative_feedback`（负面反馈，按 dimension 聚合降权）
- `material` 1—* `shortlist_item`（待选，经 `selection_task`）
- `selection_task` 1—* `task_message`、1—* `shortlist_item`、1—* `recommendation_feedback`
- `recommendation_feedback` 1—* `material_negative_feedback`（失败拆解沉淀）
- `category` 自引用（两级：parent_id），`material.category_id` 指向二级类
- `term_alias`（同义词，独立，支撑解析与检索）
- 支撑表：`operation_log`、`settings_kv`、`import_staging`、`app_meta`
- `material_fts`（FTS5 外部内容虚拟表，内容来自 `material`，由 `material_ai/ad/au` 三触发器同步）

## 6. 统一约定

| 项 | 约定 |
| --- | --- |
| 时间 | **唯一入口** `now_iso()`，东八区 ISO 8601（`2026-09-14T14:22:00+08:00`）；禁止别处取时间或写 SQL 默认值 |
| uid | 材料跨机器唯一键 = `new_uid()`（UUID4）；任务/待选/回评用本机自增 `id` |
| JSON 字段 | 库内 `TEXT` 存 JSON（`json_dumps` 用 `ensure_ascii=False`），接口层由后端展开为数组/对象 |
| 区间字段 | 恒为 `xxx_min` / `xxx_max`；单位不进值 |
| 空值 | 一律 `null`（SQLite 存 `NULL`），**禁止空字符串** |
| 错误 | 见 §3 错误码表，响应体 `{"error":{"code","message"}}` |
| 配置化 | 推荐权重（key=`weights`）、降权阈值（key=`penalty`）存 `settings_kv`，不写死 |

## 7. ADR 记录

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| ADR-01 | 用 SQLite 单文件 + WAL | 单机单用户、零运维、易备份分享（PRD §1.3） |
| ADR-02 | 材料唯一键 = `uid`(UUID)，导入三选一冲突策略 | 跨机器去重（PRD §4.5 / Q14） |
| ADR-03 | 不引入 SQLAlchemy，原生 sqlite3 + Repository 抽象 | 保持 SQL 可控 + 可平滑迁移 PostgreSQL |
| ADR-04 | 存储层抽象 + `repository/base.py` 冻结签名 | 一期就留迁移口子（PRD §1.3 末段） |
| ADR-05 | FTS5 `trigram` 优先，不支持回退 `unicode61` | 中文子串友好；兼容性兜底，启动告警 |
| ADR-06 | `now_iso()` 作为全项目唯一取时间入口 | 时间口径统一，避免时区漂移（契约 §4.6(b)） |
| ADR-07 | `init_db()` / `seed_if_empty()` 容错跳过缺失数据文件 | 数据由数据收集师异步交付，框架不依赖其存在 |
