## 1. 项目概述

### 1.1 一句话定位
MatSelect 是汽车电控工程师**个人的「材料选型决策辅助工作台」**——把分散在人脑与供应商手册里的选型经验，沉淀为可检索、可推荐、可追溯、可分享的单机知识资产。

### 1.2 一期 Must（务必交付）
| 模块 | 范围 |
| --- | --- |
| A 材料知识卡 | A1 列表（卡片/表格视图、筛选、排序）、A2 详情页（对齐截图版式 + 历史反馈）、A3 精确检索（关键词/参数区间/场景标签，中英文） |
| B 智能推荐工作台 | B1 自然语言双通道输入 + 结构化约束回显确认、B2 排序推荐列表（分数可拆解）、B3 模板化理由/注意/替代、B4 替代方案、**B5 选型任务（类 AI Chat 多轮会话）**、**B6 待选清单** |
| C 回评闭环 | C1 成功/失败/不评价；失败理由语义拆解入库（`material_negative_feedback` / `requirement_gap`）；软降权 + 盲区报告 |
| D 材料维护 | D1 新建、D2 编辑（直接生效）、D3 变更留痕 + Git 式 diff、D4 别名维护 |
| E 数据分享 | E1 导出 JSON/Excel/Markdown（含校验和）、E2 材料包导入（uid 去重 + 冲突三选一） |
| F 系统基础 | F1 两级分类维护、F2 本地操作日志；权重/降权阈值/备份配置化 |

### 1.3 一期明确不做（Not Do）
| 不做项 | 依据 |
| --- | --- |
| ❌ 角色权限 / 登录鉴权 | 单机单人（PRD §1.5） |
| ❌ 编辑审核流转 | 同上 |
| ❌ Excel/CSV 批量导入 | 二期（注意：E2「材料包导入」是分享闭环，不同） |
| ❌ 知识图谱与替代关系推理 | 二期（仅建 `material_relation` 空表） |
| ❌ 材料对比视图（多材料并排） | 二期（待选清单导出已部分覆盖） |
| ❌ 供应商/牌号级实测数据 | 视数据准备情况 |
| ❌ 移动端适配、PLM/ERP 集成、多人协同/云端同步 | 单机定位 |

### 1.4 成功指标（验收口径，PRD §2.3 + 契约 §7）
| 类型 | 指标 | 目标值 |
| --- | --- | --- |
| 效率 | 单次选材信息获取耗时 | < 3min（基线 >30min） |
| 质量 | 推荐采纳率（回评成功占比） | > 40% |
| 质量 | 推荐被标失败占比 | < 15% |
| 数据 | 材料条数 | ≥ 50 条 |
| 数据 | 参数字段完整率 | > 90% |
| 性能 | 检索响应 / 推荐响应 / 材料库首屏 | < 500ms / < 2s / < 1s |
| 沉淀 | 待选清单导出/复用次数 | 持续增长（E1 日志可采） |

## 4. 并行编排方案

### 4.1 可并发项（按里程碑分组）
| 并发组 | 并发角色 | 内容 | 隔离方式 |
| --- | --- | --- | --- |
| G1（M1） | 架构师 ‖ 技术负责人 | 后端骨架/schema ‖ 前端底座/Token/类型 | 路径天然隔离：`backend/app/**`/`backend/db/**` vs `frontend/**` 根配置，无重叠 |
| G2（M2+M3 早期） | 数据收集师 ‖ 后端专家 | 种子数据 ‖ repository/api 编写 | 数据侧只产出 `data/*.json`+`seed_data.py`；后端只读库表契约，互不改文件 |
| G3（M3+M4） | 后端专家 ‖ 前端专家 | 接口实现 ‖ 页面实现 | 前端先用 `api/types.ts` + mock 数据打通布局（原型 README §5 建议），联调阶段再切真实接口；路径 `backend/` vs `frontend/src/pages` 隔离 |
| G4（M4+M5 末段） | 前端专家 ‖ 验收专家 | 页面收尾 ‖ 用例编写 | 验收只读不写；用例与页面同仓不同目录 |

### 4.2 硬依赖项（禁止并发，须等待）
1. 架构师 `db/schema.sql` + `app/db/init_db.py` → 数据收集师 `seed_data.py`、后端 `repository/*.py`（表结构未定前不得写数据访问）。
2. 技术负责人 `api/types.ts` → 前端所有调用点（类型未定前前端用临时 mock 类型，合入即替换）。
3. 后端 API 真实实现 → 前端联调（mock 仅用于布局，真数据须等 M3 接口可用）。
4. M3 + M4 完成 → M5 验收启动。

### 4.3 并发时的文件归属隔离（防冲突硬约束）
- 每位专家仅提交自己「拥有」路径（§2）；跨文件需求一律 SendMessage 给技术负责人/lead。
- 契约 §2 目录树为唯一仲裁；新增文件须落入对应角色目录，禁止在他人目录新建。
- `docs/plan/02` 冻结，任何人不得改；如需调整须技术负责人批准并全队同步。

## 5. Git 规范落地（契约 §6）

### 5.1 分支模型
| 分支 | 用途 | 命名示例 |
| --- | --- | --- |
| `main` | 稳定可交付，仅接受 `dev` 合并，里程碑打 tag | — |
| `dev` | 集成分支 | — |
| `feat/<模块>` | 功能开发 | `feat/backend-materials`、`feat/frontend-workbench` |
| `data/<模块>` | 数据构建 | `data/seed-50-materials` |
| `test/<模块>` | 验收测试 | `test/acceptance-suite` |
| `docs/<模块>` | 文档 | `docs/plan` |
| `fix/<问题>` | 缺陷修复 | `fix/fts-trigger` |

- 专家在自己分支工作，完成合入 `dev`；里程碑末 `dev` → `main` 并打 tag。
- 分支小写 + 连字符；禁止在 `main` 直接提交。

### 5.2 Conventional Commits（type + scope 清单）
```
<type>(<scope>): <subject>
```
- `type ∈ {feat, fix, docs, style, refactor, test, chore, data, build}`
- `scope` = 模块：`materials` / `recommend` / `tasks` / `feedback` / `export` / `import` / `settings` / `ui` / `tokens` / `schema` / `seed` / `git` / `plan`
- 示例：`feat(recommend): 实现硬约束过滤与加权排序`、`data(seed): 导入首批 50 条材料`、`fix(ui): 修复待选面板空态`、`docs(plan): 补充交付计划 M2 依赖`

### 5.3 里程碑 Tag（契约 §6.3）
`v0.1.0-m0`(规划) → `v0.2.0-m1`(框架) → `v0.3.0-m2`(数据) → `v0.4.0-m3`(后端) → `v0.5.0-m4`(前端) → `v1.0.0`(验收交付)

### 5.4 每里程碑提交粒度
| 里程碑 | 建议提交粒度 |
| --- | --- |
| M0 | 计划/契约各 1 次 docs 提交；TEAM.md 1 次 |

## 6. 开放问题处置（Q4 / Q12 / Q13 / Q14）

| 编号 | 问题 | 结论 | 引用 | 影响面 | 返工范围 |
| --- | --- | --- | --- | --- | --- |
| Q4 | 参数区分典型值/保证值 | `value_type` 字段保留，默认 `typical`；前端详情页按典型值展示并标注字段类型 | ADR-05 | `material.value_type` 已预留；A2 详情页、D 编辑表单 | 零返工：仅前端展示层落实「参数类型：典型值」标签 + 免责文案 |

## 7. 风险台账（≥6 条）

| # | 风险 | 影响 | 应对 | 责任角色 |
| --- | --- | --- | --- | --- |
| R1 | 数据录入质量/数量不足（最大风险） | 检索与推荐效果差，采纳率不达标 | AI 搜集首批 50 条直接建库 + 人工抽检校对；字段完整率门禁 >90% | 数据收集师 / PM |
| R2 | 术语词典不全致召回失败 | 「保险丝座」查不到 → 用户弃用 | AI 生成初版 + 结合 C1 需求缺口报告持续补充 + 未命中反馈入口 | 数据收集师 / 后端 |
| R3 | 推荐结果不被信任 | 工程师宁问人，采纳率<40% | 匹配度分数可拆解 + 参数标注来源 + 回评可纠正 | 后端 / 前端 |
| R4 | 回评量不足致降权失效 | C1 闭环形同虚设 | 提示优先、降权为辅；阈值可下调至 1 并允许手动确认 | 后端 |
| R5 | 负面反馈误伤好材料 | 单次差评埋没优材 | 单条不降权；软降权 + 设置可清空/编辑自己反馈 | 后端 |
| R6 | 跨机器分享 ID 冲突 | E2 导入后数据错乱 | 全局 `uid`(UUID) 去重；无 uid 按「名称+简称」兜底 | 后端 |
| R7 | 单机数据丢失 | 硬盘故障=积累归零 | 每日自动备份 + 定期导出材料包（E1 兼冷备） | 后端 / 技术负责人 |
| R8 | 需求蔓延到全量材料库 | 工期失控 | 严守 §1.3 Not Do；Excel 批量导入/图谱推理推二期 | PM |
| R9 | 本地语义效果不达预期 | 排序不准 | 规则权重兜底（语义仅占 25%）；调权重即改善，无需换模型 | 后端 |
| R10 | 契约与 PRD 不一致（Tailwind/bge） | 实现分歧 | 以冻结契约为准：不引 Tailwind（ADR-03）、一期用 n-gram 近似（ADR-04），bge 留接口二期 | 技术负责人 / PM |
| R11 | 原型与 PRD 差异未拍板（待选面板位置等） | 前端返工 | 以定稿原型为准（待选=右侧常驻面板 300px 等已定） | 前端 / PM |

## 8. 验收标准汇总

### 8.1 功能完整度
- 契约 §4 全部接口（材料/推荐/任务/待选/回评/导出/导入/设置/日志/备份/健康）实现且形状一致。
- 一期 Must（§1.2）十大模块全部可用；Not Do（§1.3）均无越界实现。
- 需求 → API → 前端调用点 三者可追溯（契约 §7 末尾）。

### 8.2 性能口径
| 指标 | 口径 |
| --- | --- |
| 检索响应 | < 500ms（200 条规模，含 FTS5 检索 + 区间 WHERE） |
| 推荐响应 | < 2s（含约束抽取 + 硬过滤 + 加权排序 + 解释生成） |
| 材料库首屏 | < 1s（200 条，卡片视图） |

### 8.3 视觉红线（契约 §7 + 原型 01 规范）
- 圆角：卡片 12 / 控件 7 / Chip 5；无投影（仅 Modal 可有遮罩）。
- 唯一主按钮；数字等宽（`--font-mono`）；AntD 6 项主题覆盖生效。
- 1366×768 起无横向滚动；主内容区单层滚动。

### 8.4 四态覆盖（05 §2 清单逐行打勾）
- 每个数据面须实现：加载（骨架屏）/ 空 / 错误（区块内联+重试）/ 成功反馈（轻提示/状态变化）。
- 选材主流程 1.1、回评闭环 1.2、分享闭环 1.3 三条主线走通。
- 推荐结果为空用优化提示条而非空列表；写操作必带成功反馈。

### 8.5 键盘可达（05 §3）
- `Ctrl/Cmd+K` 搜索、`Enter` 发送、`Shift+Enter` 换行；分类树 `↑/↓/→/←/Enter`；Modal `Esc` 且焦点锁定与归还；滑杆 `←/→` 步进。
- 图标按钮带 `aria-label`；匹配度带可读文本；标记文字+颜色双编码；焦点样式统一 `outline:2px solid #1F5FD0; offset 2px`。

### 8.6 数据完整率
- 材料 ≥ 50 条；参数字段完整率 > 90%（按 material 核心字段非空比例统计）。
- 导出 JSON 内嵌校验和（契约 §4.6(a) 算法），导入校验失败拒绝写库。

## 9. 契约与 PRD 冲突登记（PM 观察）

| 冲突点 | PRD 表述 | 契约裁决 | 处置 |
| --- | --- | --- | --- |
| 样式方案 | 原型 README §4 提「CSS 变量 + Tailwind（或 AntD cssVar）」 | ADR-03 冻结**不引入 Tailwind**，纯 Token CSS + AntD 主题覆盖 | 以契约为准；Tailwind 仅作可后置选项 |
| 语义模型 | PRD §1.3/§5.3 引用 bge-small-zh 本地 embedding | ADR-04 冻结一期用「字符 n-gram + 词集」近似，仅预留 `EmbeddingProvider` 接口 | 以契约为准；bge 为二期可插拔替换，不影响一期接口 |
| 权重语义分占比 | PRD 文本称 bge 余弦占 25% | 契约 §5 同权重 0.25，但实现为 n-gram 近似 | 一致（仅实现技术不同，权重不变） |
| 支撑表定义 | PRD §4.1 未给出 category/operation_log/settings_kv/import_staging/app_meta | 契约 §4.6 由架构师补全并定义 | 契约补全 PRD，非冲突；前端/后端依赖表名与列名即可 |

> 结论：上述分歧均已由冻结契约裁决，**实现以契约 §2/§3/§4/§5 为唯一准绳**；PM 不要求额外返工，仅前端需在 Q4/Q12 落实免责与类型标签（见 §6）。
